# API Go-сервера AntiAttendance

Справочник относится к нативной Go-версии с PostgreSQL. Дата проверки:
7 ноября 2026 года. Основной протокол синхронизации — `2`.
Telegram отключён; старые анонимные способы доступа не поддерживаются.

Документ описывает реализованный контракт. Примеры содержат вымышленные
идентификаторы и токены. Проверки с PostgreSQL и Chromium выполнялись локально;
реальный вход в MIREA и поведение внешних сервисов этим не подтверждаются.

## Адреса, типы и общие правила

Система состоит из двух HTTP-сервисов и отдельного входа в панель.
Во всех дальнейших путях `BASE` означает адрес основного сервиса,
`ID` — адрес AA ID, `PANEL` — приватный адрес панели.

| Обозначение | Пример публичного адреса | Локальный адрес Compose по умолчанию |
| --- | --- | --- |
| `BASE` | `https://aa.ytc-srv.org` | `http://127.0.0.1:18080` |
| `ID` | `https://aaid.ytc-srv.org` | `http://127.0.0.1:18091` |
| `PANEL` | Не публикуется | `http://127.0.0.1:18092` |

`PUBLIC_URL` и `AAID_PUBLIC_URL` задают реальные адреса для callback и cookie.
По умолчанию это `https://aa.ytc-srv.org` и `https://aaid.ytc-srv.org`.
Go принимает публичные origin только под `*.ytc-srv.org`; для локальных
проверок также разрешены localhost и loopback IP. Произвольные внешние
алиасы в этих настройках отклоняются при запуске. Это правило относится
к адресам наших сервисов: внешние API MIREA/SSO/расписания необходимы
для их работы и не удаляются.
Заголовки и примеры ниже не означают, что HTTPS завершается внутри Go:
в типовой конфигурации TLS обслуживает внешний nginx.
Вход `BASE/panel…` закрыт nginx с `404` независимо от переданного
`X-AA-Panel`. Приватный nginx сам выставляет доверенный служебный заголовок.
Не открывайте порт самого Go-приложения в обход этого nginx.

Основные соглашения:

- JSON кодируется в UTF-8. Для JSON-запросов используйте
  `Content-Type: application/json`.
- Отметки времени обычно представлены Unix-секундами; возможна дробная часть.
  Это не миллисекунды. В расписании даты имеют вид `YYYY-MM-DD`,
  время — `HH:MM`, часовой пояс — `Europe/Moscow`.
- `account_id` — непрозрачная строка аккаунта сервера, обычно UUID.
  Это не `pulse_id`, не AA ID `user.id` и не номер пропуска.
- `version`, `session_version`, `pass_version` и `cursor` — разные целочисленные
  счётчики. Их нельзя заменять друг другом или вычислять по времени.
- Номер цифрового пропуска — десятичная строка. Не преобразуйте его в
  JavaScript `Number`: до 19 цифр могут выходить за точную целочисленную область.
- `null` означает отсутствие значения. Пустой список — `[]`.
  Некоторые поля общей карточки намеренно отсутствуют, а не равны `null`.
- Неизвестные поля могут появляться в ответах. Клиенту следует читать
  необходимые поля и сохранять совместимость с дополнительными.
- Обычные ответы API имеют `Cache-Control: no-store`.
  Статические файлы используют ETag и пере­валидацию; QR и токены не следует
  сохранять в общих кэшах или логах.
- `HEAD` не является универсальной заменой `GET`: для большинства маршрутов
  API возвращается `405`. Статические файлы поддерживают обычную HTTP-выдачу.
- CORS для произвольных сайтов не предоставляется. Браузерные запросы
  рассчитаны на свой origin.

Основные ограничения размера на уровне приложения:

| Объект | Ограничение |
| --- | --- |
| Обычный запрос основного сервиса | 200000 байт |
| Запрос AA ID | 100000 байт |
| `POST /internal/aaid/link` напрямую к Go | 4000000 байт |
| Unary gRPC-Web запрос | 65536 байт вместе с 5-байтовым кадром |
| Ответ Pulse, читаемый нативным транспортом | 1 MiB |
| Cookie Pulse как строка | 1–65536 символов |
| Список людей для `/site/mark` | 1–200 строк при явной передаче |

Прокси может устанавливать более строгие пределы: в поставляемом nginx
`client_max_body_size` равен 200000. Большой внутренний handoff идёт
напрямую между сервисами, а не через публичный nginx.

## Авторизация и разрешения

### Токен приложения

На основном сервисе пользовательские `/api/*` требуют действительного AA ID
Bearer-токена или допустимой браузерной сессии сайта. Исключение — публичный
`GET /api/version`, возвращающий только метаданные сборки. Обычный мобильный клиент использует:

~~~http
Authorization: Bearer ACCESS_TOKEN
~~~

Токен подписан Ed25519. Проверяются подпись, issuer, audience и срок действия;
по умолчанию `iss=aa-id`, `aud=aa`. Claim `mirea` задаёт проверенную
личность Pulse. `sub` — AA ID пользователя, `sid` — его устройство,
`grp` — группа, `usr` — выбранный username.
Изменять эти поля на стороне клиента нельзя.

При явно переданном неправильном `Authorization` основной сервер
не переключается на cookie. Получение `401` требует обновить access token
или снова войти, а не пробовать старые заголовки устройства.

На AA ID маршруты `/v1/me`, `/v1/me/sessions`, отзыв устройства и выход
требуют Bearer. AA ID дополнительно проверяет активность сессии и пользователя
в своей БД. Основной сервер проверяет JWT локально: уже выданный access token
может оставаться действительным до истечения срока после отзыва устройства.
По умолчанию этот срок — 600 секунд.

### Cookie и браузерные сессии

| Cookie | Сервис и назначение | Срок по умолчанию |
| --- | --- | --- |
| `aa_site` | Основной сайт, HTTP-only, SameSite=Strict, path `/` | 30 дней |
| `aaid_web` | Веб-интерфейс AA ID, HTTP-only, SameSite=Strict, path `/` | 30 дней |
| `panel_session` | Панель, HTTP-only, SameSite=Strict, path `/panel` | 12 часов |
| `aa_state` | Проверка callback, HTTP-only, SameSite=Lax, path `/auth` | 15 минут |
| `aa_next` | Разрешённый адрес возврата, path `/auth` | 15 минут |

`aa_site` и `aaid_web` помечаются Secure при HTTPS в публичной конфигурации.
Cookie панели определяется фактическим TLS-соединением с Go; поэтому панель
в стандартном Compose доступна только на localhost. При отдельной публикации
панели её TLS/cookie-политику нужно настроить самостоятельно.

`/site/state`, `/site/today`, `/site/mark`, `/site/schedule` и поиск сайта
дополнительно используют именно `aa_site`. Для мобильного дневного представления
существует `GET /api/me/today` с Bearer. Токен приложения сам по себе
не создаёт веб-сессию сайта или AA ID.

Для изменений `/panel/api/*` требуется `X-CSRF-Token`, полученный при входе
или из состояния панели. Панельная cookie не заменяет AA ID на `/api/*`.
Для изменяющих запросов основного API и сайта переданный `Origin` должен
соответствовать Host; неправильный origin получает `403`.

### Видимость и владение

| Возможность | Владелец своего аккаунта | Получатель разрешения на чужой пропуск | Панель |
| --- | --- | --- | --- |
| Карточка в снимке `/api/accounts` | Да | Только при включённом пропуске и действующем разрешении | Отдельный полный снимок панели |
| Чтение `GET /api/accounts/{id}` | Да | Нет | Панель использует своё состояние |
| Номер разрешённого пропуска в снимке | Да, если включён | Да, если включён | Да при разрешённом тестовом режиме |
| `pass-token` / `pass-code` / `pass-issue` | Да, если включён | Да, в пределах разрешения | Сам API всё равно требует AA ID |
| Профиль, ACS, attendance и прочие RPC аккаунта | Да | Нет | Диагностические маршруты панели |
| Переименование/завершение сессии/включение пропуска | Да | Нет | Да |
| Назначение группы | Нет через обычный API | Нет | Да |
| Удаление аккаунта из БД | Нет | Нет | Да |

Запрос к чужому или отсутствующему аккаунту обычно возвращает одинаковый `404`.
Группа, знание UUID, `X-Pass-Client`, `X-Pass-Test-Key`, старые Telegram-привязки
и имя устройства не предоставляют права читать чужие данные.
Настройка `AAID_ENFORCE=0` не возвращает старый анонимный режим в Go.

Отдельное правило сайта: состав урока может показывать подключённых людей
из своей группы и групп на той же паре. Это ограниченное представление
имени, группы, состояния сессии и отметки, не выдача их cookie/пропусков/профилей.

## Ошибки и ограничения

Обычная прикладная ошибка:

~~~json
{"detail":"Account not found"}
~~~

Ошибка модели может содержать список:

~~~json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "label"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
~~~

Не разбирайте человекочитаемый `detail` для бизнес-логики:
он может быть русским или английским. Используйте код HTTP, а для валидации —
`type` и `loc`. Ошибки внешнего nginx могут быть HTML, поэтому клиент должен
обрабатывать не-JSON ответы.

| Код | Значение |
| --- | --- |
| `200` | Успех, в том числе некоторые бинарные gRPC-Web ответы с ошибкой в trailers |
| `301` | Старые страницы `/login` и `/u/{id}` перенаправляются на `/` |
| `303` | Начало входа/возврат через AA ID |
| `304` | Статический файл не изменился |
| `400` | Некорректный курсор/период, QR, cookie, origin-связанные бизнес-параметры |
| `401` | Нет допустимой сессии/токена, неверный пароль, нужен повторный вход |
| `403` | Действие запрещено, неверный CSRF, выключен пропуск, блокировка AA ID |
| `404` | Нет ресурса или нет права его раскрывать; Telegram отключён |
| `405` | Метод HTTP не поддерживается |
| `409` | Конфликт версии/состояния, сессия завершена, QR-вход ещё не готов |
| `413` | Превышен размер |
| `422` | Не прошли JSON/поля/типы или Pulse не подтвердил импорт |
| `429` | Превышен лимит запросов/попыток/одновременных входов |
| `500` | Внутренняя ошибка |
| `502` | Не удалось разобрать ответ внешнего сервиса в диагностике |
| `503` | Внешняя зависимость/сервис недоступны, очередь занята |
| `504` | Тайм-аут диагностической браузерной операции |

При обязательном входе ответ основного API `401` также содержит:

~~~http
WWW-Authenticate: Bearer
X-AAID-Required: 1
~~~

~~~json
{"detail":"AA ID sign-in required","aaid_url":"https://aaid.ytc-srv.org"}
~~~

Лимиты текущего процесса:

| Операция | Лимит |
| --- | --- |
| Основной API: чтение, на личность MIREA | 300/мин |
| Основной API: изменение, на личность MIREA | 60/мин |
| Точный поиск людей | 20/мин на личность; дополнительный общий лимит поиска 60/мин |
| Создание запроса на чужой пропуск | 20/час |
| `/api/me/today` и дневное представление сайта | 30/мин |
| Отметка через сайт | 60/мин |
| Поиск расписания сайта | 60/мин |
| Вход в панель | 5 попыток/мин на адрес |
| Разблокировка тестового пароля пропусков | 8 попыток/5 мин |
| Pulse `pass-code` | 6 попыток/10 мин на аккаунт |
| Pulse `pass-issue` | 20 попыток/10 мин на аккаунт |
| AA ID: `/v1/auth/mirea` | 30/мин на адрес |
| AA ID: refresh и обмен одноразового кода | 60/мин на адрес для каждой операции |
| AA ID: запуск веб-входа | 10/5 мин на адрес |
| Изменение username AA ID | 10/час на сочетание пользователя и адреса при реальном изменении |

Где возвращается `Retry-After`, учитывайте его. Не все исторические
ограничители выставляют этот заголовок. Квоты хранятся в памяти процесса,
не распределены между репликами и сбрасываются при перезапуске.

## AA ID: токены приложения

### GET ID/health и GET ID/.well-known/jwks.json

Публичные служебные маршруты без входа.

~~~json
{"ok":true,"service":"aa-id"}
~~~

JWKS содержит `issuer`, `audience` и `keys` с полями
`kty=OKP`, `crv=Ed25519`, `x`, `kid`, `alg=EdDSA`, `use=sig`.
`x` — base64url открытого ключа. Закрытый ключ не выдаётся.
Кэшируйте JWKS; не скачивайте его для каждого запроса.

### POST ID/v1/auth/mirea

Начало сессии приложения по уже полученной на устройстве cookie Pulse.
Bearer не требуется: это точка входа. Сервер проверяет cookie через Pulse,
определяет личность и группу, связывает/создаёт AA ID.
Cookie используется для проверки и не сохраняется этим маршрутом;
подключение Pulse-сессии к основному серверу — отдельный импорт/handoff.

| Поле JSON | Тип | Требование |
| --- | --- | --- |
| `pulse_cookie` | string | Обязательно, 1–65536 символов, валидный cookie header |
| `device` | string | Необязательно, по умолчанию пусто, максимум 80 символов |

~~~json
{"pulse_cookie":"SESSION=example","device":"AntiAttendance · Windows"}
~~~

В `device` удаляются управляющие символы; пустое имя становится
`Unknown device`. Лимит активных app-сессий по умолчанию — 2.
При превышении вытесняется наиболее давно использовавшаяся сессия такого вида.

Успешный ответ `Grant`:

~~~json
{
  "access_token": "eyJ…",
  "access_expires_at": 1793952600,
  "refresh_token": "opaque-refresh-token",
  "session_id": "d92267ce-90ba-47eb-a541-6027dc247754",
  "user": {
    "id": "05f3b968-e721-4222-a53b-168185384bc3",
    "created": 1793952000,
    "username": "student",
    "group_id": 5330,
    "group_name": "Группа",
    "verified_at": 1793952000
  }
}
~~~

Основные ошибки: `400` неверная cookie, `401` Pulse-сессия недействительна,
`403` AA ID заблокирован, `503` Pulse недоступен.
Точный состав `user` задаётся публичным представлением AA ID;
не путайте его с карточкой Pulse-аккаунта.

### POST ID/v1/auth/refresh

Bearer не требуется. JSON:

~~~json
{"refresh_token":"opaque-refresh-token"}
~~~

Строка обязательна, длина 20–200. Ответ — новый `Grant`.
По умолчанию app-сессия живёт 60 дней, при refresh срок продлевается.
Access token живёт 600 секунд, если переменные конфигурации не изменены.

Refresh token одноразовый. Сначала атомарно сохраните новую пару токенов,
после этого используйте её. Параллельные refresh одним токеном запрещены:
повторное использование уже погашенного токена отзывает всё устройство.
При неопределённом результате сетевого запроса не устраивайте цикл повторов
со старым токеном; предусмотрите восстановление через новый вход.

`401` — требуется вход заново, `403` — пользователь заблокирован.

### GET ID/v1/me

Bearer обязателен. Возвращается объект пользователя **без обёртки `user`**,
дополненный `session_id` и `max_sessions`.
В отличие от `Grant`, обращение к результату имеет вид `result.id`.

### GET ID/v1/me/sessions

Bearer обязателен. Ответ:

~~~json
{
  "sessions": [
    {
      "id": "d92267ce-90ba-47eb-a541-6027dc247754",
      "device": "AntiAttendance · Windows",
      "kind": "app",
      "created": 1793952000,
      "last_used": 1793952000,
      "expires": 1799136000,
      "revoked_at": null,
      "revoke_reason": null,
      "current": true
    }
  ],
  "max_sessions": 2
}
~~~

Список относится только к текущему AA ID. Служебные поля БД могут отличаться
по наполнению; refresh-токены, их хэши и cookie здесь не возвращаются.

### DELETE ID/v1/me/sessions/{session_id}

Bearer обязателен. Отзывает указанное своё устройство. Тела нет.
Ответ `{"ok":true}`. Чужое/не найденное устройство — `404`.
Отзыв текущего устройства делает следующие обращения к AA ID недействительными.

### POST ID/v1/auth/logout

Bearer обязателен. Тела нет. Отзывает текущую сессию приложения,
ответ `{"ok":true}`. Это не удаление AA ID и не завершение Pulse-сессии
на основном сервере.

### PUT ID/v1/admin/users/{user_id}/status

Служебное администрирование AA ID, не обычный Bearer:
`X-Admin-Token` должен совпадать с настроенным `ADMIN_TOKEN` длиной не менее 24.
В Compose он задаётся через `GO_AAID_ADMIN_TOKEN`; пустое значение запрещает вызов.

~~~json
{"status":"blocked"}
~~~

Допускаются только `active` и `blocked`.
Ответ `{"ok":true}`; `403` — неправильный/не настроенный admin token,
`404` — нет пользователя. Не передавайте этот токен мобильным клиентам.

## Синхронизация аккаунтов

### GET BASE/api/version и GET ID/api/version

Публичная информация о версии установленной сборки; вход не нужен.
Это узкое исключение из авторизации, как `/health`: пользовательские API
по-прежнему требуют входа. Обработчик не обращается к PostgreSQL, Pulse или
браузеру и не проверяет работоспособность этих компонентов.

~~~json
{
  "service": "sessions",
  "version": "2.0.2",
  "commit": "unknown",
  "dirty": false,
  "protocol": 2
}
~~~

| Поле | Значение |
| --- | --- |
| `service` | `sessions` для основного сервера, `aa-id` для AA ID |
| `version` | Номер релиза из `internal/buildinfo/VERSION`, сейчас `2.0.2`; возможна явная метка сборки |
| `commit` | Полный Git commit сборки, либо `unknown` |
| `dirty` | Исходники содержали локальные изменения при сборке |
| `protocol` | Версия протокола синхронизации, сейчас `2` |

`version` — непрозрачная строка; она не гарантирует SemVer и не равна
версиям аккаунтов/сессий. Для точного сопоставления сборок используйте
`version`, `commit` и `dirty` вместе. Ответ `200`, `Content-Type: application/json`,
`Cache-Control: no-store`; неподдерживаемые методы, включая HEAD, дают `405`
и `Allow: GET`. Настройки, пути, пароли, runtime и данные пользователей
в ответ не включаются.

После переноса на Go базовый релиз — `2.0.0`; текущие исходники имеют
версию `2.0.2`. Источник номера релиза — `internal/buildinfo/VERSION`,
он встраивается в Go-бинарники даже без Git и без установщика.
При сборке через установщик Git-метаданные встраиваются в оба бинарника.
Без Git commit равен `unknown`; для архивной сборки можно явно задать
`AA_BUILD_VERSION`, `AA_BUILD_COMMIT` и `AA_BUILD_DIRTY` в окружении установщика.
Для прямого `docker compose build` используются build args `BUILD_VERSION`
и `BUILD_COMMIT`, `BUILD_DIRTY` (или соответствующие `AA_BUILD_*` в окружении Compose).
Смена переменных у уже запущенного контейнера версию бинарника не меняет:
нужна пересборка; `--no-build` сохраняет метаданные прежнего образа.

~~~sh
curl -sS https://aa.ytc-srv.org/api/version
curl -sS https://aaid.ytc-srv.org/api/version
~~~

### GET BASE/health

Публичный минимальный ответ:

~~~json
{
  "ok": true,
  "protocol": 2,
  "sync": "automatic",
  "aaid": {"required": true, "url": "https://aaid.ytc-srv.org"}
}
~~~

`200` означает работоспособность HTTP-маршрута, а не реальную доступность
Pulse, расписания, QR-входа или всех пользовательских сессий.

### GET BASE/api/accounts

AA ID Bearer или `aa_site`. Необязательный query `group_id` — положительное
64-битное целое. Фильтр применяется ко всем карточкам, включая собственную
и явно разрешённые общие. Без фильтра возвращается весь доступный набор.

Ответ `Snapshot`:

~~~json
{
  "accounts": [
    {
      "id": "52a3a3c8-1bfc-4d3b-9f8f-70c193091228",
      "label": "Имя",
      "group_id": 5330,
      "group_name": "Группа",
      "state": "valid",
      "expires_at": 1793955600,
      "checked_at": 1793952000,
      "version": 12,
      "session_version": 3,
      "pass_version": 1,
      "pass_allowed": true,
      "updated_at": 1793952000,
      "own": true,
      "pass_access": "approved"
    }
  ],
  "passes": [
    {"account_id":"52a3a3c8-1bfc-4d3b-9f8f-70c193091228","number":"1234567890123456789","version":1}
  ],
  "cursor": 501,
  "protocol": 2,
  "sync": "automatic",
  "group_filter": 5330,
  "pass_agreements_required": true,
  "pass_access_expires_at": 1793952300,
  "pass_testing_expires_at": null
}
~~~

Семантика полей:

| Поле | Значение |
| --- | --- |
| `accounts[].id` | ID аккаунта основного сервера |
| `username` | Username, скопированный из подтверждённого AA ID; может быть `null` |
| `state` | `valid`, `expired` или `unknown` по результатам проверок |
| `version` | Общая версия метаданных/синхронизации |
| `session_version` | Версия сохранённой Pulse-сессии |
| `pass_version` | Версия сохранённого номера пропуска |
| `pass_allowed` | Глобальный переключатель владельца на использование пропуска |
| `own` | Карточка принадлежит вошедшей личности |
| `pass_access` | В Go-снимке `approved` либо `disabled` |
| `passes[].number` | Строка номера либо `null`, если он недоступен/не сохранён |
| `passes[].version` | Версия номера; соответствует `pass_version` аккаунта |
| `cursor` | Курсор для следующего long poll |
| `pass_access_expires_at` | Срок локального кэширования решения о доступе, сейчас около 300 секунд |

Общая карточка не содержит `expires_at`, `checked_at`, `updated_at`.
`session_version` сохраняется для совместимости клиента. Cookie, browser storage
и зашифрованный `secret` не выдаются никому через этот снимок.
Наличие номера в старом локальном кэше не даёт права выполнять RPC:
права проверяются заново на каждом обращении.

### GET BASE/api/events

AA ID Bearer или `aa_site`. Long polling.

| Query | По умолчанию | Ограничение |
| --- | --- | --- |
| `after` | 0 | Целое ≥ 0 |
| `wait` | 25 | Целое от 0 до 25 секунд |
| `group_id` | Нет | Положительное 64-битное целое |

~~~json
{
  "events": [
    {
      "id": 502,
      "account_id": "52a3a3c8-1bfc-4d3b-9f8f-70c193091228",
      "version": 13,
      "kind": "label",
      "created": 1793952010,
      "group_id": 5330,
      "previous_group_id": null
    }
  ],
  "cursor": 502
}
~~~

Известные виды событий включают `session`, `label`, `group`, `pass`, `pass_permission`,
`delete`, `access`. Обрабатывайте неизвестный `kind` как сигнал перечитать
снимок, а не как ошибку протокола.

События не являются полными объектами аккаунтов. При изменении перечитайте
`/api/accounts` с тем же фильтром и замените доступный набор целиком:
так удаляются исчезнувшие/отозванные общие карточки.
После успешного ответа всегда сохраняйте `cursor`, даже когда `events=[]`:
сервер может пройти мимо невидимых клиенту событий.
Событие `access` адресуется собственному аккаунту получателя и будит
синхронизацию после изменения разрешений; приватное поле аудитории не выдаётся.

За один проход читается до 1000 строк журнала. Пустой ответ после тайм-аута —
нормальная ситуация. Не запускайте несколько бесконтрольных long poll на
одну и ту же синхронизацию. При отмене соединения ожидание отменяется.
Используйте HTTP keep-alive: повторное использование соединений заметно
уменьшает затраты DNS/TCP/TLS.

### GET BASE/api/groups

Авторизация обязательна. Ответ:

~~~json
{"groups":[{"id":5330,"name":"Группа","accounts":1}]}
~~~

Это группы из доступных карточек, а не каталог всех пользователей сервера.

### GET BASE/api/groups/search

Авторизация обязательна. Query `q`: меньше двух символов даёт пустой список;
длинная строка обрезается до 50 символов. Это поиск публичного расписания,
не поиск аккаунтов/людей. Ответ `{"groups":[…]}`.

### GET BASE/api/accounts/{identifier}

Только владелец. Ответ — публичная карточка аккаунта без обёртки.
Знание разрешённого чужого пропуска не разрешает чтение этого маршрута.
Чужой/отсутствующий аккаунт — `404`.

### POST BASE/api/accounts/import

Только после AA ID-входа. Подключает или обновляет свою Pulse-сессию.

| JSON | Тип | Условия |
| --- | --- | --- |
| `cookie` | string | Обязательно, 1–65536, валидный cookie header |
| `label` | string | Обязательно, 1–60 |
| `account_id` | string/null | Необязательно; при передаче должен совпасть с существующим аккаунтом этой личности |
| `expected_version` | integer/null | Необязательно, ≥ 0 |
| `expected_session_version` | integer/null | Необязательно, ≥ 0 |
| `group_id` | integer/null | Необязательно, > 0, ≤ 2^63−1; должен совпасть с проверенным `grp` |
| `group_name` | string/null | Необязательно, максимум 100 |

~~~json
{
  "cookie": "SESSION=example",
  "label": "Имя",
  "account_id": "52a3a3c8-1bfc-4d3b-9f8f-70c193091228",
  "expected_session_version": 3,
  "group_id": 5330,
  "group_name": "Группа"
}
~~~

Сервер спрашивает Pulse о владельце cookie. Другая личность — `403`;
неподтверждённая сессия — `422`; несовпадение ID/версии — `409`.
При уже рабочей сессии и отсутствии ожидаемых версий сервер может вернуть
существующую карточку, не затирая её новой загрузкой. Известная группа
сохраняется. Ответ — публичная карточка.

Импорт одной cookie не предоставляет browser storage для автоматического
SSO-продления. Оно появляется после поддерживаемого браузерного QR-входа
и внутреннего handoff либо входа из панели.

## Управление собственным аккаунтом

### GET BASE/api/me/account

Авторизация обязательна; Pulse-сессия может ещё не быть подключена.
Существующий аккаунт:

~~~json
{"connected":true,"account":true,"label":"Имя","pass_allowed":false,"group_name":"Группа"}
~~~

Если аккаунта нет:

~~~json
{"connected":false,"account":false,"label":null,"pass_allowed":null,"group_name":null}
~~~

`account` означает наличие записи, `connected` — состояние `valid`.
Наличие AA ID и наличие рабочей Pulse-сессии — разные вещи.
При обращении username собственной карточки синхронизируется с claim `usr`,
если он присутствует в подтверждённом токене.

### PUT BASE/api/me/account

Требует подключённую собственную запись, иначе `404`.
Тело — объект; поля необязательные:

~~~json
{"label":"Новое имя","pass_allowed":true}
~~~

`label` — строка 1–60 символов; после удаления пробелов имя не должно быть
пустым. `pass_allowed` — boolean. `null`/отсутствующее поле не изменяет настройку.
Ответ имеет тот же вид, что `GET /api/me/account`.
Для защиты от перезаписи конкурентного изменения используйте маршруты ниже
с `expected_version`.

### Изменение карточки по ID

Все следующие маршруты основного API доступны только владельцу.
Панельные варианты требуют панельную сессию и CSRF.
Успех — `200` с публичной обновлённой карточкой.

| Метод и путь | JSON | Особенности |
| --- | --- | --- |
| `PUT /api/accounts/{identifier}/label` | `{"label":"Имя","expected_version":12}` | Имя 1–60; expected_version необязателен, ≥ 0 |
| `PUT /panel/api/accounts/{identifier}/label` | То же | Панель может менять любой аккаунт |
| `PUT /api/accounts/{identifier}/pass-allowed` | `{"allowed":true,"expected_version":12}` | allowed обязателен; expected_version необязателен |
| `PUT /panel/api/accounts/{identifier}/pass-allowed` | То же | Панельный вариант |
| `POST /api/accounts/{identifier}/end-session` | Без тела | Удаляет cookie/browser state, сохраняет аккаунт и разрешения |
| `POST /panel/api/accounts/{identifier}/end-session` | Без тела | Панельный вариант |
| `PUT /api/accounts/{identifier}/group` | См. ниже | В Go обычному пользователю запрещено, `403` |
| `PUT /panel/api/accounts/{identifier}/group` | См. ниже | Только панель назначает/снимает группу |
| `PUT /api/accounts/{identifier}/pass` | См. ниже | Сохраняет номер уже полученного пропуска |

При несовпадении ожидаемой версии — `409`. Перечитайте карточку/снимок,
покажите новое состояние пользователю и повторите только осознанное действие.
Не повторяйте изменение бесконечно с устаревшим номером.

Назначение группы:

~~~json
{"group_id":5330,"group_name":"Группа","expected_version":12}
~~~

`expected_version` обязателен, ≥ 0.
`group_id` — `null` для снятия группы либо положительное 64-битное число.
`group_name` — `null` либо строка до 100 символов. Смена группы через панель —
доверенная административная операция; обычный импорт не может произвольно
назначить подписанную личность в чужую группу.

Сохранение номера:

~~~json
{"number":"1234567890123456789","expected_version":1}
~~~

`number` — строка 1–19 символов, дополнительно проверяется допустимый номер.
Здесь `expected_version` относится к `pass_version`, а не к общей `version`.
Маршрут не выпускает пропуск в университете, а сохраняет полученный номер.
Нужен включённый `pass_allowed`; разрешены положительные числа до 2^63−1
без ведущего нуля. Некорректный номер — `400`.

`end-session` намеренно прекращает автоматическое продление этой сессии.
Вернуть её можно новым входом/импортом. Сетевой сбой Pulse при фоновой
проверке сам по себе не должен стирать сохранённые credentials.

## Пропуска и разрешения

Все маршруты `/api/me/*` в этом разделе требуют AA ID или `aa_site` и
существующий собственный аккаунт; при отсутствии — `404`.
Разрешение направлено **от владельца пропуска к получателю**.

### Общая карточка человека

~~~json
{
  "account_id": "a391a643-f701-4576-92b3-ab82be312456",
  "username": "friend",
  "label": "Имя получателя",
  "group_name": "Группа"
}
~~~

Не используйте `id` как универсальный синоним `account_id`:
в записи запроса `id` — идентификатор **запроса разрешения**.

### GET BASE/api/me/people

Query `q` — точный username. Для Go поиск требует подключённый аккаунт
и не предоставляет полный каталог людей. Собственная запись исключается.
Query обрезается до 60 символов. Ответ:

~~~json
{"people":[{"account_id":"a391a643-f701-4576-92b3-ab82be312456","username":"friend","label":"Имя","group_name":"Группа"}]}
~~~

Пустой результат — `200` с `people=[]`. Не рассчитывайте на поиск
по подстроке имени, как в старом необязательном режиме входа.

### GET BASE/api/me/pass

Кому разрешён **мой** пропуск и какие запросы ждут моего решения:

~~~json
{
  "pass_allowed": true,
  "people": [
    {
      "kind": "aaid",
      "id": "a391a643-f701-4576-92b3-ab82be312456",
      "account_id": "a391a643-f701-4576-92b3-ab82be312456",
      "username": "friend",
      "label": "Имя",
      "group_name": "Группа"
    }
  ],
  "requests": [
    {
      "id": "request-opaque-id",
      "account_id": "another-account-id",
      "username": "another",
      "label": "Другой человек",
      "group_name": "Группа",
      "requested_at": 1793952000
    }
  ]
}
~~~

### POST BASE/api/me/pass/people

Выдать указанному человеку доступ к **моему** пропуску:

~~~json
{"account_id":"a391a643-f701-4576-92b3-ab82be312456"}
~~~

Поле обязательно, строка 1–64. Человек должен существовать и отличаться
от владельца. Успех возвращает обновлённый объект `/api/me/pass`.
Выключенный `pass_allowed` продолжает блокировать использование даже при
существующем разрешении.

### DELETE BASE/api/me/pass/people/{kind}/{identifier}

Отозвать разрешение. `kind` в Go — только `aaid`.
`identifier` — ID аккаунта получателя из `people[].id`.
Тела нет. Ответ — обновлённый `/api/me/pass`. Нет разрешения/неподдерживаемый
вид — `404`. Отзыв инициирует обновление видимости на клиенте получателя.

### GET BASE/api/me/passes

Чьи пропуска разрешены **мне**, и мои ожидающие исходящие запросы:

~~~json
{
  "passes": [
    {"account_id":"owner-account-id","username":"owner","label":"Владелец","group_name":"Группа","pass_allowed":true}
  ],
  "requests": [
    {"id":"outgoing-request-id","account_id":"other-owner-id","username":"other","label":"Другой владелец","group_name":"Группа","requested_at":1793952000}
  ]
}
~~~

Это список разрешений, не выдача cookie или полных профилей владельцев.

### POST BASE/api/me/pass/requests

Запросить **чужой** пропуск:

~~~json
{"account_id":"owner-account-id"}
~~~

Успех возвращает объект `/api/me/passes`.
`404` — нет такого владельца или это свой аккаунт.
`409` — доступ уже выдан, недавний отказ либо слишком много ожидающих запросов.
После отказа повторный запрос ограничен на сутки. Лимит вызова — 20/час.

### POST BASE/api/me/pass/requests/{request_id}/{decision}

Владелец отвечает на входящий запрос. Тела нет.
`decision` — только `allow` или `deny`.
Успех возвращает `/api/me/pass`; чужой/не найденный запрос — `404`.

### POST BASE/api/debug/pass-testing

JSON `{"password":"суточный-тестовый-пароль"}`, строка 1–256.
Требует обычную авторизацию и проверяет суточный пароль из панели.
Ответ `{"expires_at":1794009600,"day":"2026-11-06"}`.
Неверный/истёкший пароль — `401`.

В Go этот маршрут **не расширяет область аккаунтов**. Тестовый пароль и
`X-Pass-Test-Key` не обходят проверку владения/AA ID-sharing на внешнем API.
Не стройте клиентскую интеграцию на старой схеме общего тестового доступа.

## Бинарный RPC к Pulse

### POST BASE/api/accounts/{identifier}/rpc/{method}

Авторизация обязательна. Внешний адрес Pulse/произвольный URL клиент не задаёт.
Метод выбирается только из фиксированного списка ниже.

~~~http
Content-Type: application/grpc-web+proto
Authorization: Bearer ACCESS_TOKEN
~~~

Тело — **не JSON**, а один несжатый unary gRPC-Web кадр:

| Смещение | Длина | Значение |
| --- | --- | --- |
| 0 | 1 байт | Флаг `0` |
| 1 | 4 байта | Длина protobuf payload, unsigned big-endian |
| 5 | Указанная длина | Protobuf payload нужного RPC |

Кадр должен занимать всё тело, без хвоста/нескольких сообщений.
Некорректный кадр — `400`, > 65536 байт — `413`.
Даже «пустой» protobuf требует 5-байтового заголовка.

| method | RPC Pulse | Права |
| --- | --- | --- |
| `profile` | `/rtu_tc.rtu_attend.app.UserService/GetMeInfo` | Свой аккаунт |
| `attendance` | `/rtu_tc.attendance.api.AttendanceService/SelfApproveAttendanceThroughQRCode` | Свой аккаунт |
| `pass-token` | `/rtu.pulse_app.LongTimeTokenService/GetAccessTokenForDigitalPass` | Включённый свой/разрешённый пропуск |
| `pass-code` | `/rtu_tc.rtu_attend.humanpass.HumanPassService/SendVerificationCode` | То же + свежий X-Pulse-Token |
| `pass-issue` | `/rtu_tc.rtu_attend.humanpass.HumanPassService/GetDigitalPass` | То же + свежий X-Pulse-Token |
| `schedules` | `/rtu.schedule.api.PersonalScheduleService/GetSubscribedSchedules` | Свой аккаунт |
| `acs-timeline` | `/rtu_tc.rtu_attend.humanpass.HumanPassService/GetHumanAcsTimeline` | Свой аккаунт и собственный UID в payload |
| `visiting-logs` | `/rtu_tc.attendance.api.VisitingLogService/GetAvailableVisitingLogsOfStudent` | Свой аккаунт |
| `day-lessons` | `/rtu_tc.attendance.api.LessonService/GetAvailableLessonsOfVisitingLogs` | Свой аккаунт |
| `lesson-attendance` | `/rtu_tc.attendance.api.AttendanceService/GetAttendanceForLesson` | Свой аккаунт |

Payload зависит от внешнего protobuf-контракта MIREA. Сервер не превращает
этот интерфейс в универсальный REST-профиль и не принимает выдуманные JSON
структуры вместо protobuf. Для ACS есть готовый JSON-маршрут посещений,
для уроков — дневные представления ниже.
В `acs-timeline` строковое поле 1 должно точно совпасть с Pulse UID своего
аккаунта; чужой UID получает `403`.

Ответ обычно бинарный gRPC-Web. Разбирайте и HTTP-код, и `Grpc-Status`,
`Grpc-Message`, и trailers-кадр с флагом `0x80`.
HTTP `200` не гарантирует успех RPC. В частности upstream HTTP `401`
преобразуется в `200` с `grpc-status: 16` в trailers.

Сессия без cookie получает `409`. Ошибка соединения с Pulse — `503`;
сохранённая сессия при этом удерживается.
`profile` обновляет известное состояние сессии. `attendance` записывает
результат локальной отметки с источником `app`.

Порядок получения пропуска:

1. Получить свежий `pass-token` для выбранного аккаунта.
2. Использовать возвращённый Pulse-токен в `X-Pulse-Token` для `pass-code`.
3. Передать подтверждение в protobuf `pass-issue` с тем же допустимым токеном.
4. При успешной выдаче сервер сохраняет разобранный номер и обновляет
   `pass_version`; перечитать снимок.

`X-Pulse-Token` привязан к аккаунту и должен быть ранее выдан именно этим
процессом сервера. После перезапуска нужно получить новый.
Пустой/чужой/истёкший токен — `403`.
Разрешение на чужой пропуск не разрешает запускать для его владельца
`profile`, `attendance` или чтение turnstile/journal RPC.

## Сайт, расписание и посещаемость

### Вход на основной сайт

`GET BASE/auth/aaid` начинает переход на AA ID с `303` и `aa_state`.
Query `fresh=1` просит новый QR-вход; `next=/today` разрешает возврат на
дневную страницу. Другие произвольные адреса возврата не принимаются.

AA ID после подтверждения отдаёт одноразовый code.
`GET BASE/auth/callback?code=…&state=…` проверяет cookie/state, меняет code
на личность через AA ID и создаёт `aa_site`.
Успех — `303` на `/` или `/today`, ошибка — `303` на `/?signin=failed`.
Callback не является API обмена произвольных access token на cookie.

`POST BASE/site/logout` удаляет текущую `aa_site` и возвращает
`{"ok":true}`. Это не выход из приложения AA ID и не завершение Pulse.

### GET BASE/site/state

Требует `aa_site`. Тела/query нет.
Возвращает текущий контекст урока:

~~~json
{
  "me": {"group_id":5330,"group_name":"Группа","account_id":"own-id","label":"Имя","connected":true},
  "lesson": {"subject":"Предмет","type":"Лекция","location":"А-101","teacher":"Преподаватель","start":"09:00","end":"10:30"},
  "next": null,
  "active": "now",
  "had_lessons": false,
  "own_group_size": 12,
  "schedule_url": "/schedule",
  "schedule_error": null,
  "groups": [{"id":5330,"name":"Группа","own":true}],
  "people": [
    {
      "id":"own-id","label":"Имя","username":"student",
      "group_id":5330,"group_name":"Группа","session":"valid","own":true,
      "inside":true,"mark":null,"mirea":null
    }
  ],
  "aaid_url":"https://aaid.ytc-srv.org"
}
~~~

`active` — `now`, `soon` или `null`. `soon` означает, что следующая пара
начинается не позже чем через 15 минут.
`lesson`/`next` могут быть `null`. `inside` — boolean или `null`
при отсутствии данных; не подменяйте `null` значением «снаружи».
`mark` — локальная отметка с `state`, `message`, `created` либо `null`.
`mirea` — отметка внешнего журнала либо `null`, не тот же источник.

Группы объединяются, когда совпадают время и аудитория; для онлайн-занятий
используются предмет и преподаватель. Вне активной пары список людей
может быть пустым. Чужие группы вне совпавшего занятия не раскрываются.
При проблеме расписания возможно `200` с `schedule_error`, а не `503`:
клиент должен отображать это поле.

### GET BASE/site/today и GET BASE/api/me/today

Одинаковое дневное представление, но первый маршрут требует `aa_site`,
второй принимает токен приложения. Период — сегодняшний день по Москве.
Query не нужен.

~~~json
{
  "date":"06.11.2026",
  "group_id":5330,
  "group_name":"Группа",
  "lessons":[
    {
      "subject":"Предмет","type":"Лекция","location":"А-101","teacher":"Преподаватель",
      "start":"09:00","end":"10:30","state":"past",
      "groups":[{"id":5330,"name":"Группа"}],
      "marks":{"own-id":{"state":"approved","message":"Отметка получена","created":1793948400,"source":"app"}},
      "mirea":{"own-id":null}
    }
  ],
  "people":[
    {"id":"own-id","label":"Имя","username":"student","group_id":5330,"group_name":"Группа","session":"valid","own":true}
  ],
  "schedule_error":null,
  "mirea":{"5330":{"fetched":1793952000,"error":null}}
}
~~~

`lessons[].state` — `past`, `now` или `future`.
`marks` и `mirea` индексируются ID аккаунта, а корневой `mirea` — ID группы,
преобразованным JSON в строковый ключ. Отсутствующая внешняя отметка не равна
доказанному отсутствию человека. Локальные отметки учитываются с 15 минут
до начала пары; подтверждённый результат не затирается более слабым
результатом в том же представлении.

### POST BASE/site/mark

Требует `aa_site`. Отмечает выбранных людей учительским QR Pulse.

| JSON | Тип | Правило |
| --- | --- | --- |
| `qr` | string | Обязательно, 1–8192; поддерживаемый QR attendance Pulse |
| `account_ids` | array of string/null | Необязательно; явный список 1–200 |
| `own_group` | boolean | Необязательно, по умолчанию false |

~~~json
{"qr":"https://attendance-app.mirea.ru/?token=example","account_ids":["own-id","classmate-id"],"own_group":false}
~~~

`own_group=false` разрешает только людей текущей/скоро начинающейся общей
пары и требует непустой список. `own_group=true` ограничивает выбор
своей группой; если список не передан или `null`, выбирает подключённых
людей своей группы. Пустой явно переданный массив невалиден.
Неизвестная группа/нет активной пары — `409`, чужой выбранный человек —
`403` до отправки любых отметок в Pulse. Повторяющиеся ID удаляются.
QR другого назначения/хоста не принимается.

~~~json
{"results":[{"id":"own-id","label":"Имя","state":"approved","message":"Отметка получена"}]}
~~~

Проверяйте каждый результат: общий HTTP `200` не означает, что каждый человек
отмечен. Встречаются `approved`, `expired`, `error` и состояния,
полученные от парсера Pulse. Запрос может выполнить часть внешних действий
до разрыва соединения: автоматический безусловный повтор не является
гарантированно идемпотентным.

### GET BASE/site/schedule

Требует `aa_site`. Query:

| Query | Тип/значение |
| --- | --- |
| `group` | Необязательный integer, положительный выбирает другую группу; по умолчанию своя |
| `week` | Integer, по умолчанию 0; смещение недели ограничивается диапазоном −30…30 |
| `name` | Необязательная подпись неизвестной группы, обрезается до 40 символов |

~~~json
{
  "group_id":5330,"group_name":"Группа","own":true,
  "own_group_id":5330,"own_group_name":"Группа",
  "monday":"2026-11-02","week":0,
  "days":[
    {"date":"2026-11-02","weekday":0,"today":false,"lessons":[]}
  ],
  "schedule_error":null
}
~~~

При доступном расписании `days` содержит семь дней; `weekday=0` — понедельник.
Урок имеет поля `subject`, `type`, `location`, `teacher`, `start`, `end`,
`state`. Отсутствующая группа даёт пустые `days`. Проблема внешнего
расписания отражается в `schedule_error` при HTTP `200`.
Выбор чужого публичного расписания не предоставляет доступ к людям той группы.
Поле `week` отражает исходный параметр, а дата рассчитывается после ограничения.

### GET BASE/site/schedule/search

Cookie сайта обязательна. Query `q`, минимум два символа, максимум 50 после
обрезки; ответ `{"groups":[…]}`. Поиск не меняет собственную группу.

### Посещения турникетов

| Маршрут | Доступ и период |
| --- | --- |
| `GET /api/me/attendance` | Авторизованная своя запись; query days=7, разрешено 1–14 |
| `GET /api/accounts/{identifier}/attendance` | Только владелец; сегодняшний день |
| `GET /panel/api/accounts/{identifier}/attendance` | Панель; сегодняшний день |

Нужна действующая сохранённая cookie; отсутствие — `409`.
Если ни один запрос к Pulse не удался — `503`. При частично доступном
многодневном периоде возможен успешный неполный результат.

Ответ `/api/me/attendance`:

~~~json
{
  "account_id":"own-id","state":"valid","inside":true,
  "last_in":{"time":1793941200,"direction":"in"},
  "last_out":null,
  "events":[{"time":1793941200,"direction":"in"}]
}
~~~

События могут содержать дополнительные сведения из парсера ACS.
Список собственного многодневного маршрута отсортирован от новых к старым
и ограничен 30 элементами; `last_in`/`last_out` — объекты события либо `null`.
Публичный маршрут по ID и панельный вариант возвращают
`{"inside":true,"events":[…],"since":1793912400}`.
`inside` определяется по сегодняшним данным, а не последнему событию
за произвольное число прошлых дней.

## Браузерный интерфейс AA ID

Эти маршруты находятся на `ID`. Обычный Bearer приложения не заменяет
`aaid_web`. Веб-прокси подписывает короткий внутренний токен и обращается
к основному серверу от имени текущего пользователя; credentials Pulse
в браузер при этом не возвращаются.

### QR-вход: POST ID/web/logins

Начало входа без предварительной авторизации; тело не требуется.
Возвращает:

~~~json
{"id":"login-job-id","token":"opaque-login-capability"}
~~~

`token` — секрет возможности доступа к **этому** заданию. Храните его
до завершения входа; не помещайте в URL, аналитику и логи.
Очередь ограничена, одновременно браузерные входы выполняются в заданном
числе слотов. При заполнении возвращается `503`.

### GET ID/web/logins/{identifier}

Заголовок `X-Login-Token: opaque-login-capability` обязателен;
обычная веб-cookie не заменяет его.

~~~json
{"status":"login","error":null,"qr":"https://sso.mirea.ru/…","qr_png":"data:image/png;base64,…"}
~~~

Состояния: `waiting`, `login`, `finishing`, `complete`,
`expired`, `failed`, `cancelled`.
`qr` и `qr_png` могут быть `null`, пока QR не подготовлен.
`error` — безопасное сообщение либо `null`.
Неправильный токен, ID или истёкшее задание — `404`.
Задания и capability хранятся в памяти: перезапуск прерывает текущий вход.

### POST ID/web/logins/{identifier}/claim

Тот же `X-Login-Token`. Тело не требуется.
Вызывается после `status=complete`.
Результат атомарно забирается один раз; cookie/browser state удаляются
из объекта задания. До завершения и при повторном claim — `409`.

~~~json
{"ok":true,"linked":true}
~~~

Устанавливает `aaid_web` и пытается передать свежую Pulse-сессию основному
серверу. `linked=false` означает, что вход в AA ID прошёл, но подключение
Pulse-сессии к AntiAttendance не подтвердилось. Это не полная ошибка входа;
проверьте `/web/account` и при необходимости повторите новый вход.
Заблокированный пользователь — `403`.
Возвращаемая cookie предназначена веб-интерфейсу, а не подмене refresh token.

### GET ID/web/me

Нужна `aaid_web`. Возвращает публичные поля пользователя непосредственно
в корне: `id`, `username`, `group_id`, `group_name`, `created`, `verified_at`;
дополнительно `sessions`, `max_sessions`, `site_url`.
У сессий есть `current` относительно текущей веб-сессии.
Отсутствующая/недействительная cookie — `401`; блокировка — `403`.

### PUT ID/web/username

Нужна `aaid_web`. JSON:

~~~json
{"username":"student_01"}
~~~

Исходная строка 1–40 символов; сервер удаляет внешние пробелы, начальные `@`
и переводит в нижний регистр. Итоговый шаблон:
`^[a-z][a-z0-9_]{2,23}$` — 3–24 символа, первая латинская буква.
Ответ `{"username":"student_01"}`.
Неверное имя — `400`, занято — `409`. AA ID является источником username;
основной сервер получает его через подписанные данные.

### Прокси личных настроек и пропусков

Все маршруты таблицы требуют `aaid_web`. JSON-поля запросов совпадают
с соответствующими `/api/me/*`. Прокси отдаёт только выбранные поля,
поэтому его ответ может быть уже прямого ответа основного сервиса.

| Маршрут AA ID | Основной маршрут | Ответ |
| --- | --- | --- |
| `GET /web/account` | `GET /api/me/account` | account, connected, label, pass_allowed, group_name |
| `PUT /web/account` | `PUT /api/me/account` | Та же модель; JSON label/pass_allowed необязательные |
| `GET /web/people` | `GET /api/me/people` | people; query q, точный username |
| `GET /web/pass` | `GET /api/me/pass` | pass_allowed, people, requests |
| `POST /web/pass/people` | `POST /api/me/pass/people` | JSON account_id; модель собственного пропуска |
| `DELETE /web/pass/people/{kind}/{identifier}` | `DELETE /api/me/pass/people/{kind}/{identifier}` | kind=aaid; обновлённая модель |
| `GET /web/passes` | `GET /api/me/passes` | passes и requests |
| `POST /web/pass/requests` | `POST /api/me/pass/requests` | JSON account_id; исходящие разрешения/запросы |
| `POST /web/pass/requests/{request_id}/{decision}` | `POST /api/me/pass/requests/{request_id}/{decision}` | decision=allow/deny; собственный пропуск |
| `GET /web/attendance` | `GET /api/me/attendance` | inside, last_in, last_out, events |

Поля человека, разрешённые прокси: `kind`, `id`, `account_id`, `username`,
`label`, `group_name`. В `passes` добавляется `pass_allowed`.
`requested_at` и произвольные поля основного сервиса прокси не обязан отдавать.
В `/web/attendance` параметр `days` не перенаправляется: используется
стандартный период основного маршрута.

При недоступности основного сервера — `503`. Состояния «не подключён»
и конфликт переводятся в `404`/`409` с сообщением для пользователя.
Не все коды upstream прозрачно транслируются: например, прочие ошибки
основного сервера могут стать `503` на AA ID.

### GET ID/web/schedule

Нужна `aaid_web`. Расписание именно группы текущего AA ID.

~~~json
{
  "group_id":5330,
  "url":"https://schedule-of.mirea.ru/?…",
  "current":{"subject":"Предмет","type":"Лекция","location":"А-101","start":"09:00","end":"10:30"},
  "next":null
}
~~~

В отличие от недельного API сайта, это только текущий и следующий урок;
`teacher` удалён из этой модели. Без группы — `group_id=null`,
`current=null`, `next=null` и адрес корня расписания.
Недоступный внешний календарь без подходящего кэша — `503`.

### DELETE ID/web/sessions/{session_id}

Cookie AA ID. Отзывает своё устройство, ответ `{"ok":true}`.
Не найденное/чужое устройство — `404`.

### POST ID/web/logout

Отзывает найденную текущую веб-сессию и удаляет `aaid_web`.
Ответ `{"ok":true}`; отсутствие cookie допустимо.
Не стирает Pulse-аккаунт и не отзывает все app-сессии.

### POST ID/web/authorize

Cookie AA ID. Подготавливает одноразовый переход на основной сайт.

~~~json
{"state":"base64url-state-from-main-site"}
~~~

`state` обязателен, шаблон `^[A-Za-z0-9_-]{16,128}$`.
Ответ `{"redirect":"https://aa.ytc-srv.org/auth/callback?code=…&state=…"}`.
Адрес берётся из серверной `AA_SITE_URL`; произвольный redirect_uri клиент
не передаёт. Если сайт не настроен — `404`.

### POST ID/v1/site/exchange

Служебный обмен кода с предыдущего шага.
JSON `{"code":"opaque-one-time-code"}`, строка 20–200.
Bearer не нужен: секретом является сам одноразовый code.
Срок — 60 секунд; повторный/просроченный/неизвестный code — `400`.
Коды хранятся в памяти и теряются при перезапуске AA ID.

~~~json
{"id":"aaid-user-id","mirea":"pulse-person-id","group_id":5330,"group_name":"Группа"}
~~~

Это не токен приложения и не выдача Pulse-cookie.
Основной сайт обменивает код только после своей проверки state/cookie.

## Административная панель

Все пути этого раздела относятся к `PANEL`.
Публичный nginx их закрывает. Для чтения нужна панельная сессия,
для POST/PUT/DELETE после входа — также `X-CSRF-Token`.

### POST PANEL/panel/api/login

JSON `{"password":"panel-password"}`, обязательная строка 1–256.
Для новой установки пароль находится в `GO_ADMIN_PASSWORD` файла `.env.go`.
После импорта сохраняется старый пароль панели.
Вход проверяет переданный Origin, если он присутствует.

Ответ `{"csrf":"opaque-csrf-token"}` и cookie `panel_session`.
`401` — неправильный пароль, `429` — слишком много попыток.
Это отдельная панельная авторизация, не получение AA ID Bearer.

### GET PANEL/panel/api/state

Возвращает:

~~~json
{
  "csrf":"opaque-csrf-token",
  "accounts":[
    {
      "id":"account-id","label":"Имя","group_id":5330,"group_name":"Группа",
      "state":"valid","version":12,"session_version":3,"pass_version":1,
      "pass_allowed":true,"expires_at":1793955600,"checked_at":1793952000,
      "updated_at":1793952000,"username":"student",
      "automatic_renewal":true,"renewed_at":1793951900,"page_seen_at":1793951800
    }
  ],
  "cursor":501,
  "pass_testing":{"password":"суточное-значение","expires_at":1794009600,"day":"2026-11-06"}
}
~~~

`automatic_renewal` показывает наличие browser storage, а не гарантию
успеха будущего продления. `renewed_at`/`page_seen_at` могут быть `null`.
`pass_testing.password` — текущая суточная административная тестовая capability;
`expires_at` — срок, `day` — московская календарная дата.
Ни этот ответ, ни просмотр таблиц не выдают сохранённые cookie/browser state.

### GET PANEL/panel/api/pass-snapshot

Добавленный в Go панельный маршрут. Возвращает форму `Snapshot` для
панельного интерфейса без ослабления `/api/accounts`.
Поддерживает `group_id`. Доступ только по панельной сессии.
Для получения номеров тестовым интерфейсом используется суточный
`X-Pass-Test-Key` из состояния панели. Обычный Bearer пользователя
не заменяет панельную сессию.

### POST PANEL/panel/api/logout

Cookie и CSRF. Тела нет. Удаляет панельную сессию;
ответ `{"ok":true}`. Следующее чтение состояния — `401`.

### Управление аккаунтами в панели

| Маршрут | Назначение |
| --- | --- |
| `PUT /panel/api/accounts/{identifier}/label` | Переименовать; JSON label, expected_version |
| `PUT /panel/api/accounts/{identifier}/pass-allowed` | Разрешить/запретить пропуск; JSON allowed, expected_version |
| `PUT /panel/api/accounts/{identifier}/group` | Назначить группу; JSON group_id, group_name, обязательный expected_version |
| `POST /panel/api/accounts/{identifier}/end-session` | Завершить сохранённый Pulse-вход, не удаляя аккаунт |
| `POST /panel/api/accounts/{identifier}/refresh` | Проверить/при необходимости продлить сессию сейчас |
| `DELETE /panel/api/accounts/{identifier}` | Удалить аккаунт, связанные разрешения и опубликовать изменение |
| `GET /panel/api/accounts/{identifier}/attendance` | События турникетов за сегодня |
| `GET /panel/api/accounts/{identifier}/profile-fields` | Диагностическое protobuf-дерево профиля |

Тела изменений описаны в разделе управления собственной карточкой.
`refresh` — совместная с фоновой работой операция: одинаковые проверки
одного аккаунта объединяются, отмена клиента не стирает credentials.
Успех возвращает публичную карточку; отсутствие — `404`.
`DELETE` возвращает `{"ok":true}`; это удаление на сервере AntiAttendance,
не удаление университетской учётной записи.

`profile-fields` возвращает `{"grpc_status":0,"fields":{…}}`.
Ключи дерева — номера protobuf-полей, значения могут быть вложенными.
Это привилегированная диагностика персональных данных: не передавайте
её вывод в публичные отчёты без удаления персональной информации.
Нет cookie — `409`, недоступен Pulse — `503`, неразбираемый ответ — `502`.

### POST PANEL/panel/api/logins

Cookie+CSRF. Начинает управляемое подключение Pulse-сессии.
Тело должно быть JSON-объектом; допустимы необязательные поля:

~~~json
{"label":"Имя нового аккаунта","account_id":null}
~~~

`label` — `null` либо строка до 60; отсутствие не переименовывает
существующего владельца. `account_id` при продлении фиксирует нужный
аккаунт и ожидаемую `session_version`, чтобы старое задание не затёрло
уже заменённую сессию.

~~~json
{"id":"login-job-id","enrollment_path":"/enroll/login-job-id/secret-capability","expires_in":600}
~~~

Путь enrollment содержит секрет. Он разрешает работу только с этим заданием,
не чтение остальных API. Очередь/лимит заняты — `429`.
Выдаваемый `expires_in` равен 600; фактические сроки заданий также зависят
от настройки LOGIN_TTL_SECONDS, поэтому клиент обрабатывает `404`/expired.

### Наблюдение за входом и отмена

| Маршрут | Защита | Ответ |
| --- | --- | --- |
| `GET /panel/api/logins/{identifier}` | Панельная cookie | status, qr, error, account_id, label |
| `GET /panel/api/logins/{identifier}/qr` | Панельная cookie | PNG; `404`, если QR ещё нет |
| `DELETE /panel/api/logins/{identifier}` | Cookie+CSRF | `{"ok":true}` |
| `GET /enroll/{identifier}/{token}` | Секрет token в пути | HTML страницы входа |
| `GET /enroll/{identifier}/{token}/state` | Тот же token | Та же модель состояния |
| `GET /enroll/{identifier}/{token}/qr` | Тот же token | PNG |
| `POST /enroll/{identifier}/{token}/claim` | Тот же token | `{"account_id":"account-id"}` после complete |

Публичное enrollment-окно ограничено 600 секундами, панельный просмотр —
900 секундами от создания. Неизвестный/неверный/истёкший token — `404`.
Claim enrollment до завершения — `409`. Этот claim возвращает только ID
уже подключённого аккаунта и не выдаёт cookie/AA ID-токен.
Он отличается от одноразового claim **AA ID** `/web/logins/{id}/claim`.
Состояния перечислены в разделе QR-входа; `account_id`/`label` могут быть `null`.

## Диагностика и трафик

Все маршруты здесь находятся на `PANEL` и требуют входа.
Чтение диагностик не требует CSRF; запуск browser record требует.

### GET PANEL/panel/api/debug/browser

Добавленный в Go маршрут для наблюдения за памятью/скачиваниями.

~~~json
{
  "go_heap_bytes":10485760,
  "go_heap_objects":24000,
  "goroutines":28,
  "telegram_enabled":false,
  "browser":{
    "contexts":0,
    "running":true,
    "login_slots_free":6,
    "renew_slots_free":2,
    "completed_since_restart":10,
    "asset_cache":{
      "entries":4,"bytes":12582912,"hits":20,"misses":4,
      "revalidations":1,"saved_decoded_bytes":50000000,
      "downloaded_decoded_bytes":12582912,"fetches":5,
      "content_length_bytes":6500000,"unknown_content_lengths":1
    },
    "traffic":{
      "started":"2026-11-06T09:00:00Z",
      "page_network":{},
      "dropped_measurements":0,
      "api_requests":30,
      "api_decoded_bytes":20000,
      "note":"…"
    }
  }
}
~~~

Значения примера условны. Браузер запускается лениво, поэтому
`running=false` при отсутствии QR/renewal/record — нормальное состояние.
`browser` может быть `null` в конфигурации без поставщика статистики.

| Счётчик | Что измеряет |
| --- | --- |
| go_heap_bytes/objects | Go heap, не полный RSS процесса/Chromium |
| contexts | Открытые браузерные контексты |
| login_slots_free/renew_slots_free | Свободные исполнительные слоты |
| completed_since_restart | Закрытые контексты после последнего запуска браузера |
| asset_cache.bytes | Удерживаемые декодированные тела публичной статики |
| hits/misses/fetches | Попадания/промахи/фактические загрузки кэша |
| revalidations | Условная проверка через ETag/Last-Modified |
| saved_decoded_bytes | Объём повторно использованных декодированных тел |
| content_length_bytes | Сумма объявленных размеров сетевых ответов статики |
| unknown_content_lengths | Ответы без пригодного Content-Length |
| page_network | Агрегированные requests/encoded_response_bytes/failures по фиксированному host/type |
| api_decoded_bytes | Прочитанные декодированные ответы Playwright API, отдельно от page traffic |
| dropped_measurements | Измерения, пропущенные ограниченной очередью |

Не складывайте бездумно decoded и encoded-счётчики: они имеют разные
базы измерения. Это не биллинг сетевого интерфейса и не доказательство
всех исторических 200 GB. Счётчики в памяти сбрасываются при перезапуске
процесса. Метрики не сохраняют URL, QR-токены, cookie, тела ответов или ID людей.

Кэш ограничен 64 MiB/128 объектами/32 MiB на файл.
Общий кэш принимает только явно публичную статику Pulse, включая framework
runtime, и не принимает персональные/private/no-store/cookie-setting ответы.
Подробности исправлений — [browser-memory-fix.md](browser-memory-fix.md).

### GET PANEL/panel/api/debug/system

Объект с полями:

- `now`, `started` — времена;
- `process` — Go version, pid, platform, heap_kb и при Linux доступный
  `memory_kb` из VmRSS; совместимое поле `python` содержит версию Go;
- `files.postgresql_bytes` — размер БД по PostgreSQL, не размер SQLite;
- `browser` — внутренние браузерные счётчики;
- `background.refresh_loop` — состояние фоновой проверки;
- `presence` — состояние ограниченного кэша присутствия;
- `calendars` — group_id/name/fetched/failed/size/checking и совместимые поля;
- `telegram=null` — старое место в контракте, бот не работает.

`memory_kb` процесса не включает все дочерние процессы Chromium.
Диагностические поля совместимости `parsed`/`weeks` календарей не являются
полноценными счётчиками нативного парсера; не используйте их для биллинга/алертов.

### GET PANEL/panel/api/debug/requests

Query: `q` — подстрока маршрута; `errors` — boolean, по умолчанию false;
`slow` — порог миллисекунд, по умолчанию 0.
Некорректные boolean/число — `422`.

Ответ `{"since":1793952000,"recent":[…],"routes":[…]}`.
`recent` — до 300 подходящих записей из кольца 1000:
`time`, `method`, `route`, `path`, `status`, `ms`.
`routes` — агрегаты `route`, `count`, `errors`, `total_ms`, `max_ms`,
`last`, `avg_ms`, по суммарной длительности.
`errors` у агрегатов считает HTTP ≥500; фильтр recent `errors=true`
включает HTTP ≥400. Paths нормализованы по шаблону маршрута:
секретные параметры URL не журналируются.

### GET PANEL/panel/api/debug/logs

Query `after` — integer, default 0; `q` — подстрока;
`level` — `debug`/`info`/`warning`/`error`.
Ответ `{"logs":[…]}`, до 500 записей из кольца 3000.
Запись: `id`, `time`, `level`, `logger`, `message`, `detail`.
В Go это ограниченный диагностический журнал HTTP-ошибок,
не полный перехват всех stdout/Chromium/PostgreSQL журналов.

### GET PANEL/panel/api/debug/audit

Query `q` — до 200 символов; `limit` по умолчанию 500,
ограничивается диапазоном 1–2000.
Ответ `{"events":[…]}`, новые первыми. Поля события включают
`id`, `action`, `account_id`, `actor`, `created` и `label` при наличии.

### GET PANEL/panel/api/debug/tables

Ответ `{"tables":[{"name":"accounts","columns":[…],"rows":12},…]}`.
Показываются допустимые таблицы основной схемы `aa`.
Не выдаются Telegram-таблицы и старые таблицы Telegram-capability;
произвольный SQL этим интерфейсом выполнять нельзя.

### GET PANEL/panel/api/debug/tables/{name}

Query `q` — до 200 символов; `offset` по умолчанию 0,
отрицательный становится 0; `limit` по умолчанию 100, ограничен 1–500.

~~~json
{"name":"accounts","columns":["id","label","secret"],"total":12,"offset":0,"rows":[["account-id","Имя","•••"]]}
~~~

Это пример формы, не точный порядок всех столбцов accounts.
`rows` — массивы значений в порядке `columns`.
Секретные столбцы и `config.value` заменяются на `•••` **в SQL-проекции**,
до чтения значений приложением. Поиск не ищет по замаскированным данным.
Имя таблицы сверяется со списком; неизвестное/запрещённое — `404`.

### POST PANEL/panel/api/debug/pulse-record

Cookie+CSRF, JSON `{"account_id":"account-id"}`, строка 1–64.
Нужен сохранённый browser storage указанного аккаунта.
Запускает ограниченную браузерную диагностику Pulse/attendance:
до 150 секунд, 8 посещённых страниц, 500 RPC-записей и ограниченный
объём удерживаемых данных.

~~~json
{
  "visited":["https://pulse.mirea.ru/services"],
  "methods":["/rtu_tc.rtu_attend.app.UserService/GetMeInfo"],
  "calls":[
    {"host":"pulse.mirea.ru","method":"/rtu_tc.rtu_attend.app.UserService/GetMeInfo","status":200,"grpc_status":0,"request":{},"response":{},"response_bytes":100}
  ],
  "known_mutations_blocked":true
}
~~~

URL посещений очищаются от query/fragment. Известные методы изменения
посещаемости/выдачи пропусков и logout блокируются при диагностике.
При этом protobuf-деревья `calls` могут содержать **персональные данные**:
это привилегированный отчёт, в отличие от обезличенных traffic-метрик.
Не публикуйте его без проверки содержимого.
Неверное состояние — `409`, Pulse недоступен — `503`,
истечение времени — `504`.

## Служебные и статические маршруты

### POST BASE/internal/aaid/link

Внутреннее подключение свежего Pulse-входа от AA ID. Обычный клиент
не должен вызывать его напрямую. Требуется JWT в `Authorization: Bearer …`
с отдельной аудиторией `aa-link`, подписанный сохранённым ключом AA ID.
Короткий handoff-токен обычно живёт 60 секунд.

| JSON | Тип | Обязательность |
| --- | --- | --- |
| `cookie` | string, 1–65536 | Обязательно |
| `storage_state` | object/null | Необязательно; browser state для продления |
| `expires_at` | number/null | Необязательно |
| `renewed_at` | number/null | Необязательно; при отсутствии сервер использует текущее время |
| `group_id` | positive int64/null | Необязательно |
| `group_name` | string до 100/null | Необязательно |

Основной сервер повторно проверяет через Pulse, что cookie принадлежит
`mirea` из подписи. Нет/невалидная подпись — `401`;
Pulse не подтвердил ту же личность — `422`.
Ответ `{"account_id":"account-id"}`. Сохранённая группа существующего аккаунта
не затирается автоматически. Переданный `usr` синхронизирует username.
Browser state хранится зашифрованно и не возвращается в публичный API.

| Метод/путь | Сервис | Поведение |
| --- | --- | --- |

| `GET BASE/today` | Основной | HTML дневного представления |

| `GET ID/` | AA ID | HTML AA ID |

## Примеры клиента и порядок интеграции

### PowerShell: вход и чтение

Пример для Windows PowerShell/PowerShell 7. Используйте адреса своей
установки и cookie, полученную законным входом в собственную MIREA-сессию.
Не вставляйте реальные токены в публикуемый transcript.

~~~powershell
$baseUrl = 'https://aa.ytc-srv.org'
$identityUrl = 'https://aaid.ytc-srv.org'
$pulseCookie = Read-Host 'Cookie собственной Pulse-сессии'
$signInBody = @{
    pulse_cookie = $pulseCookie
    device = 'AntiAttendance test on Windows'
} | ConvertTo-Json
$grant = Invoke-RestMethod -Method Post -Uri "$identityUrl/v1/auth/mirea" -ContentType 'application/json' -Body $signInBody
$apiHeaders = @{ Authorization = 'Bearer ' + $grant.access_token }
$snapshot = Invoke-RestMethod -Uri "$baseUrl/api/accounts?group_id=5330" -Headers $apiHeaders
$snapshot.accounts | Select-Object id, label, state, version, session_version
$events = Invoke-RestMethod -Uri "$baseUrl/api/events?after=$($snapshot.cursor)&wait=25&group_id=5330" -Headers $apiHeaders -TimeoutSec 35
~~~

Это демонстрация последовательности, не готовое защищённое хранилище токенов.
В продукте храните refresh token в системном защищённом хранилище.

Обновление с **одним** конкурентным владельцем refresh:

~~~powershell
$refreshBody = @{ refresh_token = $grant.refresh_token } | ConvertTo-Json
$newGrant = Invoke-RestMethod -Method Post -Uri "$identityUrl/v1/auth/refresh" -ContentType 'application/json' -Body $refreshBody
# В приложении сначала атомарно сохранить новую пару.
$grant = $newGrant
$apiHeaders = @{ Authorization = 'Bearer ' + $grant.access_token }
~~~

### PowerShell: панель на localhost

Выполняйте на машине с доступом к приватному порту.

~~~powershell
$panelUrl = 'http://127.0.0.1:18092'
$panelPassword = Read-Host 'Пароль панели'
$panelBody = @{ password = $panelPassword } | ConvertTo-Json
$panelLogin = Invoke-RestMethod -Method Post -Uri "$panelUrl/panel/api/login" -ContentType 'application/json' -Body $panelBody -SessionVariable panelSession
$panelHeaders = @{ 'X-CSRF-Token' = $panelLogin.csrf }
$panelState = Invoke-RestMethod -Uri "$panelUrl/panel/api/state" -WebSession $panelSession
$browserStats = Invoke-RestMethod -Uri "$panelUrl/panel/api/debug/browser" -WebSession $panelSession
# Для изменений добавить -Headers $panelHeaders и -WebSession $panelSession.
~~~

Не нужно вручную посылать `X-AA-Panel` в публичный адрес:
это не пароль и не способ обойти приватный nginx.

### Пример запроса профиля как gRPC-Web

Формирование того же профильного кадра, что у нативного транспорта,
на Python без внешних библиотек:

~~~python
from pathlib import Path
host = b'https://pulse.mirea.ru'
payload = b'\x0a' + bytes([len(host)]) + host + b'\x18\x01'
frame = b'\x00' + len(payload).to_bytes(4, 'big') + payload
Path('profile-request.bin').write_bytes(frame)
~~~

Отправка с Windows curl:

~~~powershell
curl.exe --silent --show-error --request POST "https://aa.ytc-srv.org/api/accounts/ACCOUNT_ID/rpc/profile" --header "Authorization: Bearer ACCESS_TOKEN" --header "Content-Type: application/grpc-web+proto" --data-binary "@profile-request.bin" --output profile-response.bin --dump-header profile-response.headers
~~~

`profile-response.bin` — бинарный файл, не JSON.
Не используйте пример как способ читать чужой профиль.

### Рекомендованный алгоритм синхронизации

1. Прочитать `/health`, проверить `protocol=2` и требование AA ID.
2. Войти/обновить AA ID, сериализуя refresh на уровне клиента.
3. Загрузить `/api/accounts` с выбранным `group_id`.
4. Полностью заменить доступный набор карточек и пропусков этим снимком.
5. Запустить один `/api/events` с полученным cursor и тем же фильтром.
6. При событиях перечитать снимок; при пустом ответе сохранить новый cursor.
7. При `401` один раз выполнить корректный refresh; при повторном отказе
   перейти ко входу. Не стирать локально всё пользовательское состояние
   из-за одного сетевого тайм-аута.
8. При `429` выдержать Retry-After или задержку с jitter;
   при `503` применять ограниченный backoff.
9. При смене фильтра отменить старый long poll и получить новый снимок.
10. Перед использованием пропуска получать свежий account-bound Pulse token,
    даже если номер уже сохранён локально.

### Повторы, конфликты и важные различия

| Ситуация | Поведение клиента |
| --- | --- |
| Потеря ответа обычного GET | Ограниченно повторить с backoff |
| `409` ожидаемой версии | Перечитать и повторно согласовать действие |
| Потеря ответа refresh | Не бесконечно повторять использованный токен |
| Потеря ответа отметки/выдачи пропуска | Проверить состояние; внешнее действие могло выполниться |
| `404` ранее общего аккаунта | Удалить из доступного кэша после перечитывания снимка |
| `linked=false` после QR AA ID | Проверить подключение основного аккаунта; AA ID-вход мог сохраниться |
| `inside=null` | Показать «неизвестно», а не «человек вышел» |
| `schedule_error` при `200` | Показать проблему расписания, не ложное «пар нет» |
| HTTP `200` бинарного RPC | Разобрать gRPC status/trailers |
| Успешный health | Не считать доказательством доступности MIREA |

В Go намеренно изменены только согласованные области: PostgreSQL,
обязательная авторизация/ограничение данных, отключение Telegram и исправления
ресурсов/синхронизации, а также адреса сервисов под `*.ytc-srv.org`.
Нельзя ожидать прежней выдачи всех аккаунтов без входа.
Публичные карточки не содержат `pulse_id`/`secret`; ID личности доступен
доверенному серверу через подпись AA ID, а не общий каталог.

### Проверки и поддержание документации

Реестр перенесённых маршрутов:
[go-route-coverage.json](go-route-coverage.json). Он считает 97 маршрутов
исходной реализации в текущем объёме и 3 исключения Telegram.
Дополнительно Go предоставляет `/panel/api/debug/browser`,
`/panel/api/pass-snapshot` и стандартную выдачу статики.
Количество зарегистрированных маршрутов не доказывает абсолютную
совместимость с любым ответом внешней MIREA.

Проверка наличия маршрутов в справочнике:

~~~sh
python3 scripts/check_api_docs.py
~~~

Проверка локально уже запущенного стека, без входа во внешнюю MIREA:

~~~sh
python3 scripts/verify_go_stack.py --env-file .env.go
~~~

Скрипт последовательно проверяет health, JWKS, отказ анонимному доступу,
панельный вход/CSRF/выход и диагностику. Он принимает только
`http://127.0.0.1` адреса. Дополнительные параметры:
`--site`, `--identity`, `--panel`.
После импорта пароль панели может отличаться от нового GO_ADMIN_PASSWORD:
добавьте `--ask-panel-password`, чтобы ввести сохранённый пароль без
отображения и без передачи его аргументом командной строки.
Не используйте его с рабочими пользовательскими credential-файлами
без понимания того, что он создаёт краткоживущую панельную сессию.

Установка и сохранение старых ключей при переносе описаны в
[go-postgres-migration.md](go-postgres-migration.md). Менять ключи при обычном
перезапуске нельзя: это сломает расшифровку сессий или доверие старым токенам.
