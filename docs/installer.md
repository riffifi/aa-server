# Установка и обновление сервера

Главный установщик — `install.sh`, он запускает Go / PostgreSQL.
`install-go.sh` остаётся прямым входом в тот же установщик.
Старая Python-версия использует отдельный `install-python.sh`.
Интерфейс установщика, справка, ошибки и журналы выводятся на английском.
В интерактивных вопросах используйте `yes`/`no` или `y`/`n`.
Номер релиза хранится в `internal/buildinfo/VERSION` (сейчас `2.0.3`).
При сборке установщик встраивает его и Git commit в оба сервиса;
`GET /api/version` возвращает эти сведения без входа и без данных пользователей.

## Первый запуск

В каталоге репозитория на Ubuntu/Debian:

~~~sh
sudo bash install.sh
~~~

Если `.env.go` ещё нет и открыт терминал, запускается мастер. Он спрашивает
адреса сайта и AA ID, три локальных порта, способ настройки host nginx,
путь nginx.conf и необходимость HTTPS/Let’s Encrypt с email.
Затем показывает конфигурацию и просит подтвердить её.
До подтверждения настройки и контейнеры не меняются.

Адреса по умолчанию: `https://aa.ytc-srv.org` и
`https://aaid.ytc-srv.org`. Локальные порты: 18080, 18091 и 18092.
Для повторного запуска мастера — `--interactive`.
Для автоматизации — `--non-interactive`; без терминала вопросы автоматически
не задаются.

После новой установки выводятся адреса сайта/AA ID/панели, локальные порты,
пути к настройкам и журналу, имена томов для резервного копирования.
Новый пароль панели показывается в терминале. Без терминала он не выводится,
если явно не добавить `--show-password`. Все пароли остаются в приватном
`.env.go`.

При повторном запуске сохраняются существующие пароли, ключи и дополнительные
поля. Явные аргументы меняют только соответствующие настройки.
Файл настроек никогда не выполняется как shell-код.

## Проверки и зависимости

Проверяются:

- Docker CLI, Compose plugin и доступ к daemon.
- Python 3, OpenSSL и curl; nginx при выборе его настройки.
- Certbot и nginx-плагин при выборе автоматического HTTPS.
- Синтаксис Compose и существующей nginx-конфигурации.
- Свободное место на диске проекта и локально доступном диске Docker.
  Менее 4 GiB блокирует сборку с подсказкой освободить место.
- Доступная память и CPU. При свободной RAM менее 2 GiB выводится рекомендация
  освободить память или уменьшить число browser slots.
- Три локальных порта: свободны либо принадлежат этому Compose-проекту.
- DNS сайта/AA ID. Для автоматического сертификата отсутствие DNS блокирует
  установку; без Certbot выводится рекомендация.
- Конфликты server_name с другими nginx-сайтами.
- После запуска: HTTP health сайта, AA ID и приватного входа.
- После Certbot: локальные HTTPS-запросы с SNI и проверкой сертификатов.

DNS A/AAAA должен указывать на сервер либо внешний прокси. Для HTTP challenge
Let’s Encrypt порт 80 должен быть доступен извне. Локальная DNS-проверка
не подтверждает доступность через NAT/firewall.
Установщик не переписывает firewall и не меняет DNS у провайдера.

На Ubuntu/Debian недостающие пакеты устанавливаются через apt.
Docker/Compose устанавливаются из официального репозитория Docker.
При остановленном daemon установщик пытается запустить Docker через systemd.
При недостаточных правах ошибка предлагает повторить запуск с sudo.
Для других ОС зависимости устанавливаются вручную.
В режиме `check` пакеты не устанавливаются.

## Обновление и проверка

После получения новой версии исходников:

~~~sh
sudo bash install.sh update
~~~

Проверки зависимостей повторяются; отсутствующие пакеты устанавливаются.
Пароли не генерируются заново, ключи сохраняет штатный инициализатор Go.
Загружаются образы PostgreSQL/nginx, пересобирается Go-образ, проверяются сервисы.
Настройки nginx/TLS и имя Compose-проекта сохраняются для следующих обновлений.

Изменить только локальный порт:

~~~sh
sudo bash install.sh update --site-port 18080
~~~

Проверить без изменения настроек и запуска контейнеров:

~~~sh
sudo bash install.sh check
~~~

Этот режим создаёт только журнал. `.env.go` и nginx не переписываются.
Если `.env.go` отсутствует, но найдена старая `.env`, `update` автоматически
предлагает перенос Python/SQLite в Go/PostgreSQL и создаёт `.env.go`.
Пустой файл `.env.go` вручную создавать не нужно.

Подготовить только настройки:

~~~sh
bash install.sh install --no-start --non-interactive
~~~

`--no-start` не запускает сервер/nginx и не получает сертификат.
В нём по умолчанию отключена автоустановка пакетов; при необходимости
добавьте `--install-deps`. Проверки требуют доступные инструменты.

## Аргументы

Поддерживаются `--параметр значение` и `--параметр=значение`.
Команда `install`/`update`/`check` указывается перед параметрами.

| Параметр | Назначение |
| --- | --- |
| `--site-url URL` | Адрес сайта; также `--public-url`, `--url` |
| `--aaid-url URL` | Адрес AA ID |
| `--site-port PORT` | Порт сайта, по умолчанию 18080; также `--port` |
| `--aaid-port PORT` | Порт AA ID, по умолчанию 18091 |
| `--panel-port PORT` | Порт приватной панели, по умолчанию 18092 |
| `-e, --env-file FILE` | Настройки, по умолчанию `.env.go` |
| `-p, --project NAME` | Compose-проект; сохраняется для обновлений |
| `--configure-nginx` | Создать/обновить собственный managed include |
| `--no-host-nginx` | Управлять внешним nginx вручную |
| `--nginx-config FILE` | Глобальный nginx.conf; включает настройку nginx |
| `--tls-email EMAIL` | Включить nginx/Certbot и задать email |
| `--no-tls` | Не запускать Certbot, например при внешнем TLS |
| `--interactive` | Запрашивать настройки даже при обновлении |
| `--non-interactive` | Без вопросов |
| `--no-start` | Только настройки и проверки |
| `--check` | То же, что команда `check` |
| `--no-build` | Использовать существующий Go-образ |
| `--skip-pull` | Не загружать образы PostgreSQL/nginx заново |
| `--timeout SECONDS` | Ожидание готовности, 1–3600, по умолчанию 240 |
| `--install-deps` | Устанавливать недостающие пакеты; обычно включено |
| `--no-install-deps` | Только проверять зависимости |
| `--show-password` | Показать новый пароль даже без терминала |
| `-h, --help` | Полная справка |

Порты должны различаться и находиться в диапазоне 1–65535.
Сервисы публикуются на loopback; панель не открывается наружу.
Адреса — разные HTTP(S) origin без пути/credentials/query/fragment.
Разрешены `*.ytc-srv.org` и loopback.
Для host nginx/Certbot нужны отдельные DNS-имена, а не localhost.

Автоматическая установка с nginx/HTTPS:

~~~sh
sudo bash install.sh install --non-interactive \
  --site-url https://aa.ytc-srv.org \
  --aaid-url https://aaid.ytc-srv.org \
  --configure-nginx --tls-email admin@ytc-srv.org
~~~

При существующем внешнем TLS-прокси:

~~~sh
sudo bash install.sh update --no-host-nginx --no-tls
~~~

## Прогресс и логирование

~~~text
[05/11] Building Go services and Chromium
⠋ [######............]  36% | stage 00:01:12 | total 00:01:35
[OK] Building Go services and Chromium | 45% | stage 00:01:34 | total 00:01:57
~~~

Число этапов зависит от опций. Процент — доля завершённых этапов,
не оценка байтов Docker. Во время длинной команды анимируется символ
и обновляются время этапа/общее время. 100% появляется только после успеха
всех выбранных этапов. При ошибке показываются этап, код, журнал и возможное
решение; выполнение прекращается, сохранённые данные не удаляются.

| Уровень консоли | Вывод |
| --- | --- |
| `--log-level error` | Ошибки, подсказки при сбое и итоговые данные |
| `--log-level warn` | Дополнительно предупреждения/рекомендации |
| `--log-level info` | По умолчанию: этапы, прогресс, результаты проверок |
| `--log-level debug` | Дополнительно вывод команд/исполнитель этапа, без анимации |

- `--quiet` / `-q` — `error`.
- `--verbose` / `-v` / `--debug` — `debug`.
- `--plain` — без анимации и ANSI-кодов, удобно для CI.
- `--no-color` и переменная `NO_COLOR` — без цвета, анимация сохраняется.
- Без TTY/при `TERM=dumb` анимация автоматически отключается.

Низкоуровневые Docker-стрелки заменяются. Обычный режим показывает
именованные этапы вместо потока сборочных сообщений.

~~~sh
sudo bash install.sh update --log-level warn
sudo bash install.sh check --quiet
sudo bash install.sh update --debug --plain --log-file /var/log/aa-install-new.log
~~~

`--log-file FILE` задаёт новый приватный журнал; существующий файл
не перезаписывается. По умолчанию — уникальный файл в `.go-data/`, права 0600.
В нём сохраняется полный вывод команд независимо от уровня консоли.
Shell xtrace в debug не включается. Существующие пароли, master.key,
signing.key и содержимое .env.go не выводятся установщиком.
Правила показа нового пароля описаны выше.

## Nginx и сертификаты

Include `antiattendance-go-managed/services.conf` создаётся рядом с
глобальным nginx.conf. Другие сайты не удаляются. Перед изменением создаются
резервные копии, выполняется `nginx -t`, затем reload.
При ошибке восстанавливаются оба изменённых файла.

Обновление собственных блоков меняет upstream-порты, сохраняя
TLS-директивы и redirect-блоки Certbot. Смена набора доменов требует
отдельного переноса сертификатов; установщик останавливается с подсказкой.
При существующем домене в другом файле второй конфликтующий блок не создаётся:
используйте `--no-host-nginx` и измените старый upstream вручную.
Пример: `nginx/go-hosts.conf.example`.

Certbot использует существующий сертификат до приближения срока истечения.
При ошибке проверьте DNS, порт 80, NAT/firewall и внешний прокси.
При своём HTTPS используйте `--no-tls`.

Автоматический host nginx обслуживает стандартные порты 80/443.
Нестандартный публичный порт требует ручной настройки через `--no-host-nginx`.

## Перенос старых данных

Миграция SQL включена в команду `migrate`: SQLite экспортируется из
согласованной резервной копии и импортируется в PostgreSQL, а не просто
заменяется пустой базой. Создание схемы PostgreSQL выполняется установщиком.
Устаревшая таблица SQLite `devices` сохраняется в PostgreSQL как
`aa_legacy.devices`. Её ключи не действуют для авторизации и недоступны
рабочим ролям сервисов. Неизвестные таблицы по-прежнему останавливают экспорт.

Из каталога обновлённого репозитория:

```bash
sudo bash install.sh update
# Или указать исходную установку явно:
sudo bash install.sh migrate --from-python /home/aa/aa-server
```

Установщик запросит разрешение остановить Python для согласованного снимка.
Без терминала обязательны `--non-interactive --stop-python`.
Для другого старого Compose-проекта добавьте `--python-project ИМЯ`.
Целевой проект по умолчанию `antiattendance-go`; он должен быть пустым.
`--no-start` только подготавливает настройки, не останавливает Python.

Go всегда получает новые порты: сайт `18080`, AA ID `18091`, панель `18092`,
только на `127.0.0.1`. Старые порты не наследуются. Другие новые порты можно
указать через `--site-port`, `--aaid-port`, `--panel-port`.
Перед остановкой проверяются зависимости, новые порты и сборка образов.
При переносе установка зависимостей требует явного `--install-deps`;
это позволяет не обновлять Docker Engine, обслуживающий старые контейнеры,
без отдельного решения администратора.

Приватная копия `.go-data/python-backup-*` содержит SQLite/WAL, оба ключа,
старую `.env`, Compose-файл и снимок для импорта. Храните её как секрет.
Старые контейнеры и тома не удаляются. При ошибке после остановки
установщик останавливает целевые приложения и запускает ранее работавшие
Python-контейнеры. Ошибка сборки оставляет Python работающим.

После успешного импорта Python остаётся остановленным. **Переключите
существующие nginx-блоки вручную**, сохранив сертификаты и прочие настройки:

```nginx
# server_name aa.ytc-srv.org, location /
proxy_pass http://127.0.0.1:18080;
# server_name aaid.ytc-srv.org, location /
proxy_pass http://127.0.0.1:18091;
```

Проверьте `sudo nginx -t`, затем выполните `sudo systemctl reload nginx`.
До переключения публичные адреса будут обращаться к остановленному Python.
Панель используйте через SSH-туннель к `127.0.0.1:18092`; пароль остаётся
прежним. PostgreSQL наружу не публикуется.

Если перенос прерван, `.env.go` содержит `GO_PYTHON_MIGRATION_PENDING=1`:
обычный `update` не должен случайно создать новую пустую установку.
При оставшихся целевых контейнерах повторный автоматический импорт
запрещён. Изучите журнал и резервную копию; не удаляйте тома. Для чистого
повторного переноса выберите новый `--project` и `--env-file`. Если импорт
уже завершился, дальнейшее восстановление выполняйте вручную по журналу;
повторный импорт в непустую БД невозможен.

Низкоуровневый путь с подготовленным снимком:

`migrate-go.sh` использует те же этапы, уровни логирования, `--quiet`,
`--verbose`, `--plain` и `--log-file`. Также поддерживает `--timeout`,
`--no-build` и управление установкой зависимостей.
Обязательны `--snapshot`, `--master-key`, `--signing-key`.

Он не переключает host nginx автоматически. После импорта действует
прежний пароль панели. Если импорт успешен, а следующий этап запуска
не прошёл, исправьте причину и выполните `install.sh update` с тем же
файлом/проектом; повторно импортировать в непустую БД нельзя.
Полная процедура — [go-postgres-migration.md](go-postgres-migration.md).

## Проверка изменений установщика

Локальные тесты покрывают первоначальный мастер, обновление, сохранение
паролей/комментариев, уровни журналирования, ошибки сборки, перенос и nginx/TLS.
Docker/apt/DNS в этих тестах заменены макетами. Анимация и Bash-сценарии также
проверены в Linux-контейнере без сети. Пакеты и сертификаты на рабочем сервере
в ходе разработки не устанавливались.
